## 1. 产品/功能概述

将新品图生成器中基于现有图片的图像编辑能力拆为独立、可移植的模块仓库。模块包含共享逻辑、React 编辑 UI、Node 编辑服务和 APIMart 图像模型适配器，并提供本地 mock 演示与宿主接入说明。后续同类产品通过稳定接口提供所选图片、鉴权、图片读取和结果版本管理，不依赖新品图生成器的业务类型或源码目录。

## 2. 背景与问题

当前编辑功能分散在 React 组件、版本状态、提示词构建、图片坐标换算、Sharp 合成、Express 路由和 APIMart 图片任务逻辑中。只复制弹窗无法独立运行；直接复制宿主业务又会把 Plan、登录态、图片存储、版本历史和其它生图流程带入，导致难以复用和升级。

来源项目当前图像编辑使用 APIMart `gemini-nano-banana-2.1`、size `auto`、resolution `1K`。无笔迹时向图像模型提交所选原图一张；有笔迹时先将标注合成至所选图，再提交合成图一张。协议 mock 和来源实现可作为行为基线，真实模型质量和供应商可用性不属于本模块已验证事实。

## 3. 用户与使用场景

主要使用者是集成该能力的同类 AI 创作应用开发者及终端编辑用户。开发者在独立仓库消费明确的 core/UI/server/provider 接口；终端用户从图片卡片打开编辑器，输入修改要求、可选标注范围，提交后查看宿主应用生成的新版本。

## 4. 产品目标

1. 提供不依赖来源项目业务代码的完整图像编辑模块。
2. 将提示词、坐标和校验放入可独立测试的共享逻辑；将前端和服务端依赖隔离。
3. 保证有标注/无标注两种路径最终都只向图像模型发送一张图片。
4. 以注入式接口连接宿主图片读取、鉴权、密钥和结果存储。
5. 提供无真实凭证、无付费请求的本地 mock 示例和清楚的接入验收指南。

## 5. 非目标与明确不做

- 不实现商品分析、商品策划、普通重抽、指导重写 LLM、比例转换、文档导出或登录。
- 不负责宿主历史版本数据库、跨刷新恢复、云存储、项目状态或业务卡片。
- 不在本次自动接入新品测试或其它四个项目；宿主集成另行确认范围。
- 不新增公共 npm 发布、云端托管、多供应商策略或收费后台。
- 不新增矩形/多边形选择、自动分割或供应商原生像素级 mask；画笔是提示性标注。
- 不保证生成式模型逐像素保持未标注区域、严格遵从修改或永久提供结果 URL。
- 不进行真实 APIMart 调用，不在示例放入凭证，不宣称真实成图质量已验证。

## 7. 用户流程

1. 宿主用户从图片卡片选择一个版本，宿主固定本次 `sourceId` 与图片引用后打开编辑器。
2. 用户输入 1–2,000 字符的非空编辑要求，可选使用三档画笔、红/黄/蓝标注、橡皮擦、撤销、重做和清空。
3. 前端把来源引用、文本与可选透明标注 PNG 交给宿主注入的执行函数。图像内容必须通过宿主受控服务读取。
4. 服务端验证权限、格式、字节和解码尺寸；有标注时将其合成至源图副本。无论有无标注，provider 接口只接收一个图像输入。
5. APIMart adapter 上传该图，创建图像任务、轮询并规范化结果。实际供应商接收状态未知时不盲目重新提交。
6. 浏览器请求派发后编辑窗关闭，由宿主显示进度；派发前失败留在弹窗。失败回调携带安全错误及提交状态，宿主可恢复草稿；成功回调包含固定来源和操作 ID。
7. 宿主负责保存结果、追加新版本和选择状态。取消编辑不改源图，模块自身不管理宿主版本历史。

## 8. 功能需求

### REQ-01：分层与独立性

模块须在独立仓库中按 `core`、`react`、`server`、`adapters/apimart` 分层，提供显式入口。`core` 不依赖 DOM、React、Node 或网络；`react` 不导入 server、Sharp 或密钥；服务端通过注入的图片 loader、图像合成器、provider 和配置运行。不得引用父目录源码、Plan/ProductData、登录 hook 或宿主全局 store。

验收 AC-01：在没有来源项目 checkout 的环境安装/构建/运行 mock 示例；入口依赖检查确认浏览器产物不含 Node/Sharp/provider key，模块代码没有来源目录导入。若分层越界或需父目录才能运行则失败。

### REQ-02：编辑器输入与画笔

编辑器接收宿主提供的图片 ID/引用、打开状态和执行/回调接口。编辑文字必填，trim 后不得为空，最大 2,000 字符并显示计数。画笔提供小/中/大三档、红/黄/蓝三色、橡皮擦、撤销、重做和清空；清空无需二次确认。画布依据图片实际显示区域和 contain 缩放换算坐标，留白区域不产生标记。画笔只作用于透明覆盖层，不修改源图。

验收 AC-02：覆盖空白文本、2,000/2,001 字符，工具状态与撤销重做；在宽高比不一致和不同显示尺寸下绘制，检查留白过滤、输出覆盖尺寸及源图字节不变。任一限值/坐标/源图不变量错误则失败。

### REQ-03：草稿与派发时序

每个操作固定 `operationId` 与 `sourceId`。输入/本地预检失败不触发关闭；浏览器 HTTP 请求派发时通知宿主并关闭编辑窗；该通知不表示 APIMart 已接受任务。提交失败须由 `onError` 返回结构化错误，供宿主恢复文字和笔迹；成功才清理草稿。执行中禁止重复提交。关闭弹窗不等于取消已派发任务。组件关闭态应可保持挂载以保留草稿。

验收 AC-03：以 transport 事件记录时序，证明预检失败保持打开、派发后关闭、错误返回并能恢复相同来源草稿、重复点击不产生并发操作；未知提交状态不触发自动付费重试。任一时序/恢复错误则失败。

### REQ-04：提示词合同

有笔迹时，最终提示词由单图标注前缀、用户原文、保真后缀组成；无笔迹时为用户原文和保真后缀。中文标注前缀固定为：“提供的图片上有用户标记，用于指出需要修改的范围或内容。请根据用户要求完成修改，标记只用于定位，最终图片中不要保留这些标记。”中文后缀固定为：“保持原图其他区域的细节不变，保持原图的色彩不变”。英文使用等义模板；混合语言交由模型适配。用户原文不得重写或删减。标注颜色只表示位置，不代表修改动作。

验收 AC-04：对中、英、混合语言及空白边界执行快照/字符串断言；有无笔迹前缀分支正确、原文完整可核对且后缀位于末尾。任何原文变化、错误前缀或漏后缀则失败。

### REQ-05：标注合成和单图约束

服务端通过宿主注入的 loader 按受控图片引用读取源图，不接受未校验的任意远程 URL。检查 MIME/格式、输入字节上限（默认建议 20 MiB）、解码尺寸上限、标注 PNG 与源图像素尺寸相同。存在标注时把笔迹合成在源图副本上；不存在时直接使用源图。任何情况下 provider.generate 只能收到一张图。

验收 AC-05：用实际图像解码/合成函数和 provider 输入捕获验证有标注发合成图一张、无标注发原图一张；不同尺寸、损坏图、超限字节/像素和越权来源均拒绝，且源图未变。发送 0 张或 2 张、越权加载或跳过限制则失败。

### REQ-06：APIMart 图像任务适配

默认模型 `gemini-nano-banana-2.1`、size `auto`、resolution `1K`，由服务端配置控制且不从宿主普通生图模型选择器继承。adapter 负责图片上传、任务创建、状态轮询和输出解析，支持供应商响应中单个字符串 URL 与 URL 数组的实际类型；没有可用 HTTP(S) 结果 URL 时失败。通过注入 fetch/transport 做无网络合同测试。

验收 AC-06：mock 上传、创建、轮询覆盖成功、明确拒绝、超时、网络中断、字符串/数组结果和无效 URL；确认请求模型参数、调用次序和单图载荷正确。任意错误被伪装为成功或配置进入客户端则失败。

### REQ-07：宿主接口与版本回调

公开接口只依赖稳定的 `ImageEditInput/Result/Failure`、`execute`、`source` 和 UI 回调。Result 回传 operationId、sourceId、imageUrl、实际 prompt、provider、model。模块不得保存/覆盖宿主版本；宿主只可按结果携带的 sourceId/operationId 将成功结果追加到对应来源。来源切换时迟到结果不能写到新选中版本。

验收 AC-07：隔离宿主示例切换选中版本后再完成旧操作，确认结果仍携带旧来源并且示例只追加到对应版本；公共接口无来源业务类型、登录状态、数据库对象或模块内部历史列表。任一跨来源污染/覆盖原图则失败。

### REQ-08：安全错误和重试

失败对象至少包含 `code`、`stage`、`safeMessage`、`retryable`、`submissionState`，阶段覆盖输入、读取、合成、上传、提交、轮询和结果解析；状态为 `not_submitted/submitted/unknown`。不得向浏览器返回凭证、Authorization、Base64 或供应商完整原始响应。供应商安全审核拒绝时最多进行一次安全澄清重试，澄清只能前置，不改变用户原文和保真后缀。提交状态未知时不自动重复付费请求。

验收 AC-08：对每阶段构造错误并断言字段/脱敏、重试边界和用户文本保留；unknown 不再次调用供应商。错误泄露敏感内容、无限重试或未知状态自动二次提交则失败。

### REQ-09：独立演示与接入文档

提供独立 React + Node 示例、合成/公开本地素材和 mock provider；不要求真实 APIMart Key。README 与详细指南说明分层、前后端接线、版本归宿、请求时序、密钥/图片安全、安装/构建（实现后真实命令）、常见问题和验收步骤。未经实现验证的 API/包路径须标为示意，不能伪装为可用。

验收 AC-09：清除来源仓库访问后，按 README 从干净 checkout 完成依赖安装、测试、构建并启动 mock 示例；逐项按指南完成最小集成演练。步骤不完整、需要真实密钥或引用来源路径则失败。

### REQ-10：来源范围保护和验证

实施只发生在独立模块仓库；不得变更新品图生成器、其他四个应用或父工作区业务代码。提取行为需与来源基线对照，差异写入文档。按 TDD 完成 core、服务、APIMart 合同测试、React 交互/坐标测试、示例构建和依赖边界检查。真实模型/成本测试仅在用户另行授权后执行。

验收 AC-10：模块功能测试、类型检查、生产构建、mock 演示与 Harness 全通过；来源项目和相邻项目工作树/内容未被本任务修改；真实调用未授权时无网络模型请求。缺少任一内部验证或发生范围外修改则失败。

## 9. 数据、状态与业务规则

公共输入草案：`operationId`、`sourceId`、图片引用、原始编辑指令、可选透明标注 PNG。结果携带同一操作/来源 ID、生成图引用、实际提示词和模型元数据。编辑器状态为 idle → preparing → dispatched/waiting → succeeded/failed。草稿按来源隔离，仅当前页面内存保留，不承诺刷新恢复。宿主掌管图片版本、项目存储、任务展示和结果持久化。

## 10. 页面与 UI 需求

提供可独立使用的 React 编辑弹窗；沿用来源现有深色背景、紫蓝主操作风格作为视觉参考，但样式必须局部隔离，不影响宿主全局样式。包含预览图、编辑要求文本框/字数计数、笔刷粗细/颜色、橡皮擦、撤销/重做/清空、取消和提交；桌面和窄屏可操作。准备中/派发后/失败/禁用状态需明确。真机样式和可用性须通过隔离 mock 页面检查，不能以单元测试代替。

## 11. 异常、边界与安全规则

拒绝空/超长文本、不可读/非法/超限图片、尺寸不匹配 overlay 和越权引用。图片显示成功不代表服务端可访问；使用宿主受控 loader，避免直接 fetch 任意 URL，并对重定向、DNS 解析地址、私网/回环、字节和像素资源设置策略。凭证仅由服务端 key getter 取得，禁止进入 props、客户端包、错误、日志和示例真实配置。网络/轮询超时区分提交状态，未知不盲重发。用户取消不得影响原图或已提交任务。

## 12. 兼容性与限制

首版以 React UI 与 Node 服务为目标；具体 React/Node 支持矩阵在依赖与构建验证后记录。非 React 宿主可复用 core/service 合同并自建 UI；非 Node 后端需要适配服务合约。首版本地版本化构建产物或受控源码包，不承诺公共 npm。标注是视觉指引，不是像素掩码；保真后缀不构成像素完全不变保证；云 URL 生命周期由宿主处理。

## 13. 影响范围

仅独立模块仓库：新增 `src/core`、`src/react`、`src/server`、`src/adapters/apimart`、测试、React+Node mock 示例、真实 package exports/scripts 和接入文档。父目录导航按需更新。来源项目只作为读取基线，不作本任务代码变更。准确文件名单由实现阶段模块计划展开。

## 14. 验收标准

AC-01 至 AC-10 定义完整成功和失败条件。内部验收须包括独立环境安装、core/server/adapter 合同、坐标与画笔 UI、单图请求捕获、服务错误/安全测试、mock 示例和产物边界。Codex 负责本地功能验收和页面样式检查；真实 APIMart 请求及视觉质量未包含在本 PRD 验收中。
