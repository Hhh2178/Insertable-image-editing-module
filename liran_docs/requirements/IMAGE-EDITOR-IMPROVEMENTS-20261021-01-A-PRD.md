## 1. 背景与问题

APIMart 的结果图片字段在已观察结构中可以是字符串数组，例如 `data.result.images[0].url`。当前解析器能处理 `images` 数组中的对象及其字符串 URL，但不遍历对象字段内部的 URL 数组，因此有效结果可能被当作缺失结果。该错误会影响最终图片 URL 规范化；本 PRD 只处理这一项。

## 2. 目标与非目标

目标是在不改变现有字符串响应和 provider/service 合同的情况下，安全读取已确认字段中的 URL 字符串或字符串数组，并在一个候选非法时继续验证同一字段后续候选。

本批不新增公共接口，不更改任务提交、轮询、错误结构、模型/尺寸、提示词、指导模式或结果存储；不做任意响应递归，不请求真实供应商，不改 A+ 或其他宿主。

## 3. 功能需求

### REQ-A01：兼容字符串和候选数组

针对现有明确支持的结果字段，字段值可为单个 URL 字符串或 URL 字符串数组。数组顺序作为候选优先级；解析器返回按顺序找到的首个有效候选。保持既有字符串结果不变。

### REQ-A02：逐候选安全验证

每个候选都必须独立执行 URL 解析与安全检查。仅接受 `http:` 或 `https:`，必须有 hostname，且不得含 username/password。空值、非字符串项、无效 URL、其它协议和带凭据 URL 均跳过。首个候选无效时，继续检查后续候选。

### REQ-A03：限定解析路径与失败行为

只在 `normalizeApimartImageUrl` 当前支持的明确字段路径内处理结果，不对任意对象递归搜集 URL。所有已知路径均无有效 URL 时返回 `undefined`，让现有上层失败处理继续生效；不得返回输入图或任务详情 URL作为成功结果。

### REQ-A04：回归和兼容

新增测试覆盖嵌套 URL 数组、有效后项、空数组、非法候选、未知结构；现有字符串 URL、APIMart 请求体、任务轮询、安全错误和 Nano 参数用例继续通过。不得修改旧成功/失败结构。

## 4. 验收标准

| 编号 | 条件 | 通过标准 |
| --- | --- | --- |
| AC-A01 | `data.result.images[0].url` 为有效 URL 数组 | 规范化返回第一个有效 URL |
| AC-A02 | 数组首项非法、后续项有效 | 跳过非法项并返回后续首个有效 URL |
| AC-A03 | URL 数组为空、元素为空/非字符串或全部非法 | 返回 `undefined`，不抛出未处理异常 |
| AC-A04 | `javascript:`、其它非 HTTP(S)、含用户名/密码、格式错误 | 候选被拒；同数组后续安全候选仍可成功 |
| AC-A05 | 既有 URL 字符串响应和已支持字段结构 | 结果与修复前保持一致 |
| AC-A06 | 未知/任意嵌套字段包含看似 URL 的值 | 不递归提取，不把未知字段伪装成结果 |
| AC-A07 | 全仓回归及放行检查 | adapter 测试、`npm test`、`npm run build`、Harness 检查/测试、`git diff --check` 和最小 tarball 消费检查通过；不新增公共导出 |
