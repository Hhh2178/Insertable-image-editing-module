## 流程档位

推荐深度 UI 流程：目标 1 文档/微观任务与验收准备；目标 2 编辑器 UI 壳和隔离页面样式检查；目标 3 TDD 完成服务/provider/core 接线、内部测试和已确认的 Codex 页面/功能验收。完整流程条件未命中：此工作是在已建独立规划仓库内提取一个明确能力；范围局限单模块仓库，不涉及数据迁移、生产权限变更或多应用同步。

最低档位安全门禁：涉及公共接口和多层跨边界实现，至少深度；UI 功能需要独立页面检查，因此采用深度 UI。未采用标准流程是因为公共 API、图像服务和 React 画笔形成跨层改造；未升级完整流程是因没有多个大型模块同时改造或项目级范围条件。

## 阶段门禁

1. 用户确认正式 PRD 1.0 前，不修改产品源码。
2. 确认后先补完整任务/接口/验收拆分；文档目标通过后才能做 UI 壳。
3. UI 壳检查通过后才能接入真实 React 状态与服务调用。
4. 真实 APIMart 请求不在已确认范围内，除非用户另行授权。

如后续确认涉及宿主项目直接迁移、公共发布、认证/存储协议或真实付费验收，需基于新证据重评。
