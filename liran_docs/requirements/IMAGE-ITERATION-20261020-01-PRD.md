## 1. 产品/功能概述

在现有可移植单图编辑模块之外，增加一条可选的“带指导意见重新生成”能力：服务端使用独立改写模板，把所选版本的完整生图提示词与用户本轮意见交给一次 LLM，得到完整修订提示词后调用宿主的普通生图函数。空指导沿用普通重抽，跳过文字改写。图像编辑继续使用已实现的单图 Nano Banana 2.1 编辑链路，不经过指导改写 LLM。

提供可选 React 指导输入 UI、core 模板/输出校验、注入式服务编排和本地 mock 双流程示例。商品策划、普通生图模型、图片存储、鉴权、版本历史和任务状态仍由宿主负责。

## 2. 背景与问题

当前仓库已有图像编辑弹窗、core 提示词、Node 服务、Sharp 合成和 APIMart Nano Banana 2.1 adapter。但本地示例默认 mock，成功只更新状态文字，未显示/追加新图片版本。仓库没有普通生图适配器，也没有指导改写模板或调用链。

来源新品图生成器的指导流程使用独立改写模板：把本屏策划、原完整生图提示词、商品事实/参考资料和用户指导作为基线，返回更新策划、完整修订提示词及摘要，再将修订提示词直接交给生图请求。来源 `Plan/ProductData` 和业务接口不适合作为通用模块公共类型。

## 3. 用户与使用场景

集成模块的开发者将其接在已有图片版本卡片下。终端用户可选：按当前方案重抽、提供指导后重生，或打开图像编辑器直接改当前选中图片。操作者能区分重生与图像编辑，并查看每次结果作为独立历史版本。

## 4. 产品目标

1. 复用现有图像编辑服务，不重复增加隐式 LLM 调用。
2. 增加明确可选的独立改写模块，不修改旧提示词模板。
3. 非空指导只调用一次改写 LLM，随后调用宿主普通生图；改写结果是完整提示词，可直接传递。
4. 空指导零次改写，按当前方案普通重抽；不把空文本作为图像编辑要求。
5. 固定操作来源与版本分支，成功时追加版本；失败不覆盖旧图，生图重试不重复改写。
6. 通过注入合同适配不同宿主，不引入新品项目的业务类型或强制使用其生图模型。
7. 提供可视 mock 示例和接入文档，清楚区分 mock 流程与真实成图验收。

## 5. 非目标

- 不移入商品分析、商品策划模型、SKU 分析、登录、存储数据库或新品项目全局 store。
- 不修改已有分析/策划提示词，不把指导改写合并进旧模板。
- 不让 LLM 选择模型、供应商、工具、服务路由、图片引用或改变权限。
- 不由模块实现通用普通生图供应商；宿主注入 `generateImage`。首版不新增文字模型 APIMart adapter；宿主注入 `rewrite` 调用器。
- 不在模块端持久化真实宿主图片历史；示例的版本状态仅用于本地 mock 会话。
- 不宣称重生与局部编辑等价，也不保证生成模型逐像素保留未标记部分。
- 不连接真实宿主、不调用付费图像/文字模型、不发布 npm、不部署线上服务。
- 不自动把图像编辑后的像素内容同步成完整生图提示词；真实视觉变化与用户指令分开记录。

## 6. 保留的现有图像编辑合同

1. 当前选中版本由宿主固定为 `sourceId/imageRef`，请求另带 `operationId`。
2. 用户编辑文字必填，1–2,000 字符；画笔标注为可选。
3. 有标注时服务端将透明笔迹合成至源图副本，模型仅收到一张合成图；无标注时仅收到一张原图。
4. 有标注时提示词为单图标注前缀 + 用户原文 + 保真后缀；无标注不添加标记前缀。中文保真后缀沿用现有合同。
5. 使用现有 Nano Banana 2.1、auto、1K APIMart adapter；请求和密钥留在服务端。
6. 结果通过 `sourceId/operationId` 返回，由宿主保存并追加版本。

既有编辑模块验证见原任务文档；本 PRD 不重新解释旧验收记录。新示例须显示 mock 生成结果并追加到本地会话版本，不能只显示“成功”字样。

## 7. 用户流程

1. 宿主图片卡片将当前选中版本冻结为来源快照，提供完整生图提示词、生成方案（可选）、参考素材清单和约束。
2. 用户选择“按当前方案重抽”或“带指导意见重生”；另保留“图像编辑”入口。
3. 空指导按普通重抽，直接使用当前生成方案/素材，不调用改写 LLM。
4. 非空指导进入独立模板/改写接口。派发宿主请求后关闭指导弹窗，主界面显示阶段状态。
5. 模块校验 JSON 结构，宿主校验业务策划字段、屏位、引用和固定事实。失败或 blocked 时停止，不调用图像模型。
6. 成功时宿主保存完整候选提示词/策划快照，再把完整修订提示词和宿主选定素材传给普通生图函数。
7. 成功生成后按冻结来源追加版本。生图明确失败时保留候选策划/提示词；“只重试生图”不再调用改写器。
8. 图像编辑仍直接以当前选中图片为输入，完整走现有单图编辑链路。

## 8. 功能需求与验收标准

### REQ-01：增量公共边界

在原包中新增独立可选入口，不改变现有 `core/react/server/adapters/apimart` 导出含义。指导接口不依赖新品 `Plan/ProductData`；领域对象以 `unknown` 或调用方泛型承接，宿主负责业务校验。前端包不得导入 Node、Sharp、文字模型 provider 或密钥读取代码。

**AC-01：** 原有导入、构建与编辑测试保持有效；指导入口可单独导入；浏览器依赖检查中无 Node/Sharp/模型密钥。源码中无父目录/新品应用导入。

### REQ-02：独立版本化改写模板

新增 `guided-image-revision/1.0.0`，输入含操作上下文、来源策划或 null、所选版本的完整生成提示词、锁定事实、参考资料 manifest、生成合同、可选历史编辑要求和用户本轮指导。用户指导 1–2,000 字符。模板规则要求局部修改、用户意见优先、删除意见消解冲突正向描述、其余尽量保留、输出完整可直接生图的提示词；模板与原生图模板隔离。

**AC-02：** 测试拒绝空/超长指导；覆盖删除意见、保留未提及约束、prompt-only 和有策划输入、不可控数据不得改变输出协议。成功输出不得是提示词补丁或模型调用指令。

### REQ-03：输出结构与业务校验

改写成功只返回 `status: ok`、`updatedPlan`（无策划输入为 null）、非空 `revisedImagePrompt`、非空摘要数组。受阻只返回 `status: blocked` 和原因。core 校验字段集合和类型；宿主验证业务 schema、不可变 ID/屏位/来源引用/安全事实，不能把结构校验称为业务正确性证明。

**AC-03：** 缺字段、多余字段、错误类型、空 prompt、空摘要、blocked 混入成功字段及跨屏/引用越界策划均阻断生图，错误安全可读。

### REQ-04：一次调用与空指导分流

非空指导调用一个注入的文字改写器；结果通过结构校验和宿主业务校验后再调用图像生成器一次。空白指导走普通重抽，零次文字改写。图像编辑继续零次文字改写。审核拒绝重试不得改变用户原文；不自动增加第二个文本模型步骤。

**AC-04：** provider spy 精确断言三类路径调用数；改写失败/blocked/校验失败时生图 0 次；非空成功为改写 1 次、生成 1 次；空指导为改写 0 次、生成 1 次；编辑为文字改写 0 次。

### REQ-05：完整提示词直传

`revisedImagePrompt` 是完整可直接使用的 prompt。宿主生成阶段将其传入普通生图能力，不再调用原 prompt 拼装器，不追加过期普通 prompt。原始参考图由宿主按规则交给图片模型；改写器只接收已声明并可授权读取的事实或素材。

**AC-05：** 捕获两阶段输入，确认改写器收到完整来源基线/用户意见，生成器收到完整修订 prompt；被删除的冲突正向描述没有在后续拼装阶段重新出现；模型不能改写素材 ID、模型配置或路由。

### REQ-06：可注入的宿主编排

模块仅编排 `rewrite(context)`、宿主 `validatePlanRevision(...)`、宿主 `generateImage(...)` 和候选/结果回调。新 text adapter 和普通生图 adapter 均非必需，宿主必须在服务端注入。客户端只提交 source/operation ID、模式和用户输入，权威图片、计划、prompt、权限及密钥由宿主解析。

**AC-06：** mock Host Adapter 验证鉴权上下文、权限 loader、prompt/result 传递；请求中未授权 URL/策划覆盖权威快照时阻断。

### REQ-07：引导 UI、编辑入口与状态

独立示例提供按当前方案重抽、带指导重生、图像编辑三个入口。指导文本可选，最多 2,000 字符；空文本点击时按普通重抽。图像编辑要求非空。派发后指导弹窗关闭，主页面显示改写/生图阶段；派发前校验失败留在窗口。请求期间阻止重复提交并固定来源。

**AC-07：** 页面覆盖三个入口、空/非空分流、字数限制、派发时序、失败草稿恢复、状态呈现和来源切换。派发后不得一直停在输入窗或无状态提示。

### REQ-08：候选策划与重试

改写成功后，将完整 prompt、宿主策划候选、摘要、参考快照和 sourceVersionId 作为一次 pending 候选。图像生成明确失败时保持旧图，保留候选供只重试生图；失败不得覆盖旧图。提交受理状态未知时标记待确认，不自动创建第二个付费图像任务。

**AC-08：** 模拟改写成功/生图失败，再点只重试生图时改写调用不增加、图像调用增加一次；确认旧图仍在，pending 源 ID 不变。未知提交不执行第二个生成请求。

### REQ-09：版本快照与编辑后继续生成

模块不拥有宿主历史数据库；本地示例实现会话态版本列表，每次成功图像操作追加版本并记录 `sourceVersionId/operationId/operationType`、图片、完整 `generationPrompt` 与单次 `operationPromptUsed`。图像编辑短指令不可取代完整生图 prompt。可选 `sourceEditHistory` 只表示历史用户要求，不证明它们在图片中实际实现。没有该历史时，重抽不承诺继承只存在于像素中的内容。结果按提交时固定来源追加。

**AC-09：** 对普通重抽、指导重生和图像编辑分别生成 mock 版本；核验每版 prompt 字段、来源和历史保留。模拟切换来源/迟到回包，不发生跨来源覆盖。

### REQ-10：错误与安全边界

指导阶段错误独立区分 `context/rewrite/validate/generate/store`，不塞进图像编辑的 `ImageEditStage`。安全错误不返回供应商 raw response、模型 key 或图片 Base64。宿主 loader 限制图片权限、请求体、像素尺寸和网络来源。提交状态未知时不自动重发。

**AC-10：** 每阶段注入失败并验证错误字段、草稿、pending 状态及调用数；浏览器包无服务端凭证/路由；越权来源测试阻断。

### REQ-11：示例结果可辨认

本地 Express + React 示例无网络、无需密钥。Mock provider 返回仓库内可展示的本地样例结果，版本条反映最新选中结果；页面标记 mock。真实服务只能由目标宿主后端单独配置。

**AC-11：** 从 UI 完成空指导重抽、非空指导重生和图像编辑的完整 mock 操作；显示结果预览/版本/操作类型，成功失败可观察；无外部模型/API 请求。

### REQ-12：验证与文档

更新 Harness 必需入口、浏览器边界检查、npm scripts、模块 exports、README 和接入指南。文档区分已有/新增接口，示例代码不得伪装成已实现 API。Codex 执行功能和页面样式验收；真实模型、宿主和窄屏真机不在本 PRD 内。

**AC-12：** 新增测试、原编辑测试、类型检查、构建、Harness、client boundary 全通过；mock 页面样式有真实记录；文档接口与 package exports 一致。

## 9. 数据与状态合同

推荐通用上下文：`sourceId/sourceVersionId/operationId`、`sourceImagePrompt`、可选策划快照、锁定事实和参考资料 manifest、`renderingContract`、`operationContext`、可选 `sourceEditHistory`、`userGuidance`。客户端不提交权威策划或任意图片 URL。成功结果包含完整 `revisedImagePrompt`、策划或 null、摘要；宿主结果版本分存完整生成 prompt 与单次操作 prompt。

状态顺序：`validating → rewriting? → validating-candidate → generating → storing → succeeded`。失败区分上下文、改写、策划校验、生图、受理未知和保存。刷新恢复与任务持久化由宿主处理；当前 APIMart adapter 没有面向宿主的 taskId 查询/恢复 API。

## 10. UI 需求

本地示例图片版本卡片下提供三个同级入口。指导弹窗显示可选文本、计数、提交、取消；空指导提示按普通方案重抽。编辑器保留必填文字、画笔和单图语义。提交后指导弹窗关闭，主页面显示当前阶段和错误；成功追加新 mock 版本，失败保留旧图/候选。沿用深色紫蓝风格及样式隔离，页面样式由 Codex 检查。真实宿主、窄屏手机实测不属于本 PRD。

## 11. 安全与异常

权威图片、计划、prompt 和参考图只能从宿主授权的 source ID 解析。模型输出不可信：模块先验证结构，宿主再验证字段 allowlist、引用、固定事实和 screen identity。普通生图模型由宿主确定，LLM 无权改变。Key 只在后端读取。超时后受理状态未知时禁止自动重发；生成成功而保存失败时只重试保存。图像编辑单图合同不变。

## 12. 兼容性与限制

新增能力通过显式可选入口提供，原有编辑 API 不变。目标 React UI 和 Node 服务。宿主可以只用模板/校验并自建 UI；非 Node 后端需适配服务合约。包保持私有本地构建方式，不发布公共 npm。

prompt 层可验证修订文本已移除冲突正向描述，不能证明生成图遵循要求。真实“去掉口罩”等视觉成品必须单独检查；mock 不证明真实模型效果。

## 13. 影响范围

仅独立模块仓库：拟新增 `src/guidance/` 合同/模板/校验和服务入口、可选 React 指导 UI、mock Host Adapter、示例会话版本容器、测试和 package optional export；编辑 adapter 复用，普通生图由宿主注入。更新 README、接入指南、架构、Harness 索引、追踪和验证文档。不改其它应用，不改原图像编辑 PRD 1.0。
