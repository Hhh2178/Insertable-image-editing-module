# 图像编辑可移植模块 · 需求整理

任务 ID：IMAGE-EDITOR-MODULE-20261019-01。状态：已整理并转换为正式 PRD 1.0，等待用户确认。

## 1. 用户目标与明确范围

用户希望将新品图生成器的图像编辑能力提取到独立仓库，后续在同类产品中接入。已选择完整模块而非只复制弹窗；当前指令是“先定方案，建立 Harness”，不立即搬迁源码。

来源项目已提交推送的版本是 `7da64f7ec6dedb6defbf0fe700ad9d62e990c742`。本仓库独立于来源仓库；不依赖父目录代码、运行中的服务或已登录浏览器。原话见[授权记录](../用户原话.md)。

## 2. 必须继承的功能

| 编号 | 需求 |
| --- | --- |
| REQ-01 | 对宿主给定的当前图片提供图像编辑弹窗和最多 2,000 字符的必填文字要求；无图片时不能提交。 |
| REQ-02 | 提供小/中/大画笔、红/黄/蓝颜色、橡皮擦、撤销、重做、清空；画笔用于圈选/涂抹定位，不修改已保存原图。沿用 contain 留白坐标修正。 |
| REQ-03 | 有笔迹时，宿主/服务端读取选中原图并合成标注副本，仅把合成图发送给模型；无笔迹时只把选中原图发送给模型。两种情况模型输入都只有一张。 |
| REQ-04 | 有标记前缀按单图解释标记与编辑位置，要求最终图不要保留标记；用户原文逐字保留；所有编辑要求后追加保真后缀。中文原句为“保持原图其他区域的细节不变，保持原图的色彩不变”，其它语言等义表达，混合语言交由模型适配。 |
| REQ-05 | 首个供应商适配器为 APIMart，编辑模型默认 `gemini-nano-banana-2.1`、size auto、resolution 1K；模型配置在服务端。模型与凭证不从普通生图页面选择器隐式继承。 |
| REQ-06 | 提交前完成输入/图片检查；实际派发后关闭编辑弹窗，在宿主显示进度；失败可恢复原文本/笔迹，成功才清除草稿并回调结果。用户取消只清理当前草稿，不影响原图。 |
| REQ-07 | 每次操作固定 sourceId 和 operationId；成功结果携带来源。宿主自行将结果追加为版本/保存到项目，模块不覆盖旧图、不操作 Plan/ProductData。 |
| REQ-08 | 提供独立前端、core、server、provider 入口和接入示例。前端不导入 Node/Sharp/密钥代码；更换宿主不需要复制新品策划、登录或数据库。 |
| REQ-09 | 供应商失败、超时、上传失败、图像不匹配等有结构化安全错误；不泄漏密钥/Base64；请求是否已提交未知时，不自动重复付费提交。安全审核重试最多一次且原文与保真后缀保持。 |
| REQ-10 | 提供无真实网络的测试、隔离演示和接入指南；先验证独立模块，再由用户指定宿主做接入，不自动改其它产品。 |

## 3. 本轮不包含

- 不提取普通重抽、带指导意见改写 LLM、商品分析、策划生成、比例转换或文档导出。
- 不实现图片版本数据库、账号登录、浏览器持久化、云存储、计费或多租户后台。
- 不新增真正的矩形/多边形选区工具、像素级 inpainting mask 或自动分割；现有圈选是画笔标注。
- 不保证生成式模型使未标注区域像素逐点完全一致；保真后缀是编辑要求，实际视觉遵循度须另行验证。
- 不创建远端仓库、不发布 npm 包、不部署在线服务、不使用真实模型进行本轮规划验证。

## 4. 已查证来源与风险

来源 `ImageIterationShell.tsx` 混合普通重生/指导弹窗/编辑弹窗；`PlanCard.tsx` 负责选中版本、请求和成功追加。提示词在 `imageEditRequest.ts`，坐标在 `imageCoordinates.ts`，图片合成在 `server/composeMarkedImage.ts`，路由和图像读取仍在 `server.ts`。APIMart 上传/轮询位于大型 `server/services.ts`。

因此只拷贝一个 React 组件不足以复用完整功能；提取时必须切断宿主业务类型、私有图片存储和供应商凭证依赖。来源初次提交前已修复 URL 字符串/数组兼容、指导重试来源 ID、安全重试保留原文三处问题。现有 URL 安全校验只按主机文本检查，未验证 DNS 解析结果；不得在新模块中将其直接宣称为完整 SSRF 防护。
