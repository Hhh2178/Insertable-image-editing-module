# 图像编辑模块架构与接入契约方案

状态：PRD 1.0 已确认；目标 1/3 接口合同、目标 2/3 UI 壳、目标 3/3 实现与 mock 集成验收均已通过。需求来源见[正式 PRD](requirements/IMAGE-EDITOR-MODULE-20261019-01-PRD.md)。本文件是模块边界与接口方案的唯一来源；执行记录见[实施方案](plans/IMAGE-EDITOR-MODULE-20261019-01-实施方案.md)。

## 1. 单仓库、分入口

当前源码结构已建立如下，公开导出以 `package.json` 与各 `index.ts` 为准。

```text
src/
  core/                 # 纯 TypeScript 类型、校验、提示词、坐标
  react/                # ImageEditorDialog、画笔层、工具栏、样式
  server/               # 编辑用例、图片校验/合成、结构化错误
  adapters/apimart/     # 单图上传、提交、轮询、结果兼容
examples/react-express/ # 独立 mock 演示、宿主接入范例
tests/                  # 跨层合同和导入边界验证
```

未来提供 core、react、server、adapters/apimart 四个显式入口。core 不依赖 DOM、Node、React 或网络；react 仅引用 core，不引用 server/provider。server 接收图片解析与供应商适配器；APIMart 模块不导入任何来源项目业务代码。宿主无需使用 React UI 时，也可以直接使用 core/server。

首版不拆四个 npm 仓库或上线独立服务。先把同一仓库的边界、演示、测试和本地分发做通，避免版本发布与部署成为接入前置条件。发布公共包须另行确认。

## 2. 宿主与模块职责

| 能力 | 模块负责 | 宿主负责 |
| --- | --- | --- |
| 输入图片 | 显示、坐标换算、校验与合成 | 选择哪个图片版本，提供稳定 sourceId 和图片引用 |
| 编辑界面 | 文字、画笔、撤销/重做/清空、草稿生命周期 | 按钮位置、弹窗打开、主界面进度区 |
| 提示词 | 单图标记语义、用户原文、保真后缀、安全重试澄清 | 不注入商品策划/指导重写 LLM；可提供明确语言提示 |
| 生成请求 | 编辑流程和供应商适配器、参数、结果规范化 | 路由鉴权、密钥读取、预算与调用授权 |
| 结果 | 回传 imageUrl、promptUsed、来源和操作 ID | 追加图片版本、策划快照、存储、导出与持久化 |
| 本地图片 | 调用注入 loader 并校验返回的字节/MIME | 解析自定义图片存储引用及允许的图片来源 |

来源项目的 Plan、ProductData、登录 cookie、customImageStore、apiFetch 封装均不能成为模块硬依赖。版本条、普通重抽、带指导意见修改提示词、比例转换属于宿主；本次不把整个 ImageIterationShell 原封不动拷走。

## 3. 前端公共契约草案

以下是已冻结并进入源码的接口形状；以 TypeScript 实际导出为准：

```typescript
interface ImageEditInput {
  operationId: string;
  sourceId: string;
  imageRef: string;
  instruction: string;
  markedOverlayPngDataUrl?: string; // 透明 PNG 标注图；不会作为第二张模型图
}

interface ImageEditResult {
  operationId: string;
  sourceId: string;
  imageUrl: string;
  promptUsed: string;
  provider: string;
  model: string;
}

type ExecuteImageEdit = (
  input: ImageEditInput,
  events: { onDispatched(): void },
) => Promise<ImageEditResult>;

interface ImageEditFailure {
  code: string;
  stage: 'input' | 'load' | 'compose' | 'upload' | 'submit' | 'poll' | 'result';
  safeMessage: string;
  retryable: boolean;
  submissionState: 'not_submitted' | 'submitted' | 'unknown';
}

interface ImageEditorDialogProps {
  open: boolean;
  source?: { id: string; imageRef: string; previewUrl: string };
  disabled?: boolean;
  execute: ExecuteImageEdit;
  onClose(): void;
  onSuccess(result: ImageEditResult): void;
  onError(error: ImageEditFailure): void;
}
```

宿主提供 `sourceId` 与不透明的 `imageRef`；`previewUrl` 只用于浏览器显示，不作为服务端可任意抓取的地址。模块创建唯一 `operationId` 并在一次提交中固定两者，不随用户后来切换版本改变。宿主注入 execute，模块不固定浏览器 API 路由、登录或请求库；宿主需在服务端确认当前 principal 对 imageRef 有读取权限。`onDispatched` 表示宿主浏览器 transport 即将/已经调用 HTTP fetch；它不是 APIMart 已接受任务的确认。服务端以结构化失败的 `submissionState` 区分未提交、已提交和状态未知。

标注通过透明 PNG Data URL 从浏览器传输；HTTP 适配层负责严格校验 data URL 头、Base64、解码字节和图像尺寸。标注和原图可分别到达宿主服务进行本地合成，但 provider 合约只接受一个最终 Buffer。Express 路由只放在示例中，不作为核心模块的强制框架依赖。

```typescript
interface ImageEditProviderInput {
  model: 'gemini-nano-banana-2.1';
  size: 'auto';
  resolution: '1K';
  prompt: string;
  images: [{ bytes: Uint8Array; mimeType: 'image/png' | 'image/jpeg' | 'image/webp' }];
}

interface ImageEditProvider {
  generate(input: ImageEditProviderInput): Promise<{
    imageUrl: string;
    provider: 'apimart';
    model: string;
  }>;
}

interface ImageEditServiceDependencies {
  loadImage(imageRef: string, principal: unknown): Promise<{ bytes: Uint8Array; mimeType: string }>;
  provider: ImageEditProvider;
  principal: unknown;
  limits?: { maxSourceBytes?: number; maxOverlayBytes?: number; maxPixels?: number };
  language?: 'zh' | 'en' | 'auto';
}
```

以上接口与当前导出对齐。APIMart key getter 属于 `createApimartImageProvider` 的 adapter 配置，不属于通用 service options；不能把 `previewUrl` 当作 `imageRef`，也不能在模块默认 loader 中抓取任意 URL。

UI 默认保留当前三档粗细 4/9/18 和三色标记、橡皮擦、撤销/重做/清空。标注层使用原图尺寸和 contain 内容区坐标映射；留白不创建笔迹。草稿只在页面内存保存，并与 sourceId 绑定，不把 A 图笔迹套到 B 图。

状态为 idle → preparing → dispatched/waiting → succeeded/failed。输入或本地图像准备失败留在窗内；execute 发出 onDispatched 时关闭，由宿主显示生成进度。失败通过 onError 回调给宿主；宿主可以重新打开保留同一 sourceId 的编辑器恢复文字/笔迹。成功才清草稿；明确取消则清当前草稿。宿主可用 disabled 禁止重复提交。关闭窗口不等于取消已提交的供应商任务。

## 4. Node 服务和供应商接口

服务用例通过构造参数注入：loadImage（图片引用解析）、composeMarkedImage（Sharp 默认实现）、provider.generate（生成适配器）及服务端模型配置。

服务处理顺序：校验指令/来源 → loader 读取所选图 → 校验 MIME、20 MiB 字节上限与解码尺寸 → 若有笔迹则校验 PNG 和同尺寸并合成 → 构建最终提示词 → provider 只接收一张图片 → 规范化结果 → 回传实际使用提示词和原始来源/操作 ID。

原图可作为合成阶段输入传到本地服务端；“只发送一张图”指发送给图像模型的输入。有标注时不能再把干净原图作为第二张模型参考图，也不能把透明笔迹单独当作待编辑图片。

APIMart 适配器默认 `gemini-nano-banana-2.1`、size auto、resolution 1K。注入的服务端 key getter 仅在构造 Authorization 时使用；客户端 props、结果、错误和日志不出现 key。可配置 fetch 以便无网络合同测试，但不在生产实现加入 testOnly 分支。

适配器处理图片上传、异步 task_id 与状态轮询，按类型解析 string/array 图片 URL。缺少有效结果不得返回成功。轮询间隔和总超时应在服务端明确配置；超时/连接断开而服务商是否已接收未知时，返回结果未知，禁止自动重复付费提交。

安全审核明确失败时可进行一次带安全澄清的重试；澄清只能加在原 prompt 之前，不能替换用户原文，保真后缀仍位于末尾。不自动增加文字改写 LLM。

## 5. 提示词合同

有标注：单图标注前缀 → 用户原文 → 保真后缀。

无标注：用户原文 → 保真后缀，不附带虚构的标注说明。

中文单图前缀：提供的图片上有用户标记，用于指出需要修改的范围或内容。请根据用户要求完成修改，标记只用于定位，最终图片中不要保留这些标记。

中文后缀：保持原图其他区域的细节不变，保持原图的色彩不变

用户文字（包括有意的首尾空白）不得被重写；判空可 trim，但构造 prompt 使用原串。中文/英文使用等义约束；混合语言让模型适配。标注颜色不是固定的“删除/替换”指令，实际动作以用户文字为准。

## 6. 错误与安全边界

错误至少包含 code、stage、safeMessage、retryable、submissionState；明确区分输入、图片读取、合成、上传、提交和轮询。submissionState 区分 not_submitted / submitted / unknown。错误不回显供应商完整响应、凭证、授权头或完整 Base64。

宿主路由负责权限和可访问图片范围。默认模块不得直接接受任意远程 URL 后 fetch；loader 需要受控上传引用/白名单/解析后地址限制及对应测试。来源的主机文本过滤不是完整 DNS/SSRF 防护；网络策略由宿主声明，模块不能静默放宽。尺寸校验既检查传输字节，也需防解码后超大画布造成资源耗尽。

首版不承诺精确像素掩膜、背景绝对不变、跨刷新恢复或供应商全链路取消；这些需要额外产品/API 能力，不能从本次画笔副本语义推导出来。

## 7. 接入与分发路径

先在本仓库构建独立 React + Node 演示，使用合成图及 mock provider 证明无来源业务依赖。之后经用户指定宿主接入：前端增加打开弹窗并注入 source/execute/onSuccess/onError；服务端注入 loader、APIMart adapter 和鉴权；onSuccess 将结果追加到宿主历史。

首个分发方式建议带版本的本地构建包（可用 npm pack 生成 tgz），通过显式入口导入；开发时可用本地依赖验证，交付物不可依赖开发机父目录。公共 npm、独立云服务、其他供应商作为后续需求，不在首轮默认实现。
